# warm_alarm_macos

macOS implementation. Swift 6.1, macOS 10.15+. Uses `UNUserNotificationCenter` + `AVAudioPlayer`. **No `AVAudioSession`** — macOS does not expose it; lifecycle handling is AppKit/`NSApplication`.

## STRUCTURE

```plaintext
lib/warm_alarm_macos.dart                                  # WarmAlarmMacOS extends WarmAlarmPlatform implements WarmAlarmEventsApi
lib/src/messages.g.dart                                    # GENERATED Pigeon Dart bindings
pigeons/{messages.dart,copyright.txt}                      # Pigeon source of truth
macos/
  warm_alarm_macos.podspec                                 # CocoaPods: FlutterMacOS dep, osx 10.15, Swift 6.1
  warm_alarm_macos/
    Package.swift                                          # SwiftPM manifest (PrivacyInfo.xcprivacy is a TODO placeholder)
    Sources/warm_alarm_macos/
      WarmAlarmPlugin.swift                                # plugin entry; AppKit lifecycle hooks; kill-warning
      WarmAlarmDelegate.swift                              # UNUserNotificationCenter delegate; AVAudioPlayer; fade; snooze reschedule
      WarmAlarmStore.swift                                 # UserDefaults-backed Codable schedule store
      Messages.g.swift                                     # GENERATED Pigeon Swift bindings
```

## WHERE TO LOOK

| Task                         | Location                                                                       |
| ---------------------------- | ------------------------------------------------------------------------------ |
| Notification scheduling      | `WarmAlarmPlugin.swift` + `WarmAlarmDelegate.swift`                            |
| Audio playback / fade-in     | `WarmAlarmDelegate.swift` (no `AVAudioSession`; `DispatchWorkItem` fade steps) |
| App-lifecycle (kill-warning) | `WarmAlarmPlugin.swift` (`NSApplication` notifications)                        |
| Persistence                  | `WarmAlarmStore.swift`                                                         |
| Wire-to-public mapping       | `lib/warm_alarm_macos.dart`                                                    |

## CONVENTIONS

- This package is a **separate copy** of the `warm_alarm_ios` Swift implementation, not a symlink/include. Behavioral changes must be applied here too. Diff against `warm_alarm_ios/ios/warm_alarm_ios/Sources/warm_alarm_ios/` after any non-trivial change to keep them aligned.
- Use AppKit (`NSApplication`) — never reference `UIApplication` here.
- Test directory is intentionally absent at `macos/.../Tests/`; Dart unit tests live in `test/` and exercise the wire-mapping layer.

## ANTI-PATTERNS

- Don't edit `Messages.g.swift` or `lib/src/messages.g.dart`. Edit `pigeons/messages.dart` and run `melos run generate`.
- Don't add `AVAudioSession` calls — the symbol is unavailable on macOS and will fail to compile.
- Don't enable Wake-check or Live-Activity capabilities here. Keep `getCapabilities()` reporting them as `unsupported`.

## KNOWN WARNINGS

### `Messages.g.swift` — non-`Sendable` completion capture

`Messages.g.swift` (generated by Pigeon) emits a Swift concurrency warning about capturing a non-`Sendable` type in a `@Sendable` closure. The file is generated code and must not be edited by hand. Builds succeed at all current Xcode / Swift language-mode settings.

**Do not fix inline.** Revisit when upgrading Pigeon, Xcode, or enabling Swift 6 strict concurrency mode. File a Pigeon issue upstream if the warning persists after a Pigeon upgrade.

## NOTES

- macOS emits the same event subset as iOS: `WarmAlarmScheduled`, `WarmAlarmFired`, `WarmAlarmStopped`, `WarmAlarmSnoozed`, `WarmAlarmFailed`. No wake-check / retrigger events.
- Sandboxed entitlements are the consuming app's responsibility (e.g., `com.apple.security.network.client` is not needed; notification entitlements are not required at the plugin level).
